description: GospelFix 프로필 사이트 개선 작업을 서브에이전트 오케스트레이션 패턴으로 진행
---

`$ARGUMENTS`로 요청된 개선 작업을 아래 순서로 진행한다.

1. **분류**: 요청이 UI/코드 변경인지, 콘텐츠(카드 데이터) 변경인지 판단.
   - 코드/UI 변경 → `frontend-builder` 서브에이전트에 위임
   - 카드 콘텐츠(JSON) 변경 → `content-editor` 서브에이전트에 위임
   - 둘 다 필요하면 콘텐츠를 먼저, 그다음 이를 반영하는 UI를 순차로 위임

2. **리뷰**: 구현이 끝나면 `qa-reviewer`(컨벤션·XSS·경로 체크리스트)와 `senior-code-reviewer`(설계 판단·엣지케이스·과설계 여부)를 병렬로 호출해 diff를 검토시킨다. 두 리뷰는 관점이 다르므로 서로의 결과를 대체하지 않는다. 지적 사항이 있으면 원래 구현 에이전트에게 다시 위임해 수정한다.

3. **검증**: 리뷰를 통과하면 `browser-tester` 서브에이전트로 실제 브라우저에서 동작을 확인한다 (UI/레이아웃/인터랙션에 영향이 있는 변경일 때만; 순수 텍스트/데이터만 바뀐 경우는 생략 가능).

4. **배포 점검**: 사용자가 커밋/푸시를 원하면, `deploy-guardian` 서브에이전트로 git 상태와 시크릿 유출 여부를 점검한다.

5. **커밋 & 배포**: `deploy-guardian` 점검을 통과하면 `git-publisher` 서브에이전트에 위임해 커밋 생성과 `main` push까지 실행한다. 이 저장소는 사용자가 커밋+push 완전 자동화를 승인했으므로 push 단계에서 별도 확인을 구하지 않는다. 점검에서 문제가 발견되면 push하지 않고 사용자에게 보고한다.

각 단계 결과는 사용자에게 한두 문장으로 요약해서 보고하고, 다음 단계로 넘어가기 전 중대한 문제가 발견되면 멈추고 사용자에게 알린다.
